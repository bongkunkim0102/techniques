## 0. 최종 판단

이 프로젝트는 “외국 점성술 사이트를 한국어로 복제한 모음집”이 아니라 **원문 근거를 추적할 수 있고, 학파의 이견을 보존하며, 계산 예제를 재현할 수 있는 한국어 점성술 지식망**으로 구축한다.

권고 조합은 **LLM Wiki 방식의 편집 파이프라인 + 위키의 문서 연결·변경 이력 + Wikidata 방식의 주장·한정자·출처 + 전문 백과사전의 심사 + Astro 기반 정적 출판**이다. LLM이 공개 문서를 임의로 덮어쓰는 자동 위키는 채택하지 않는다. 모든 학파를 수집 대상으로 삼되, 출처 확인·권리 확인·번역·편집·계산 검증·공개 상태를 각각 분리한다.

이번 패키지에는 455개의 **탐색 후보**와 37개의 **자료원·설계 참고 기록**이 들어 있다. 후보에는 기법뿐 아니라 학파, 개념, 계산 기준, 문헌, 비교 대상도 있다. 이 수치는 검증된 기법 수, 완성 문서 수, 수집된 원문 수가 아니다. 자료원의 하위 문서를 전수 수집한 상태도 아니다.

**최종 도착점:** 콘텐츠·검색·편집·테스트·권리 검사가 끝난 고정 릴리스 산출물과 배포·복구 절차를 준비하되, 실제 DNS 연결·운영 Worker 배포·비밀키 등록·원격 데이터베이스 변경은 별도 승인 전까지 하지 않는다.

## 1. 이번 조사에서 확인한 사실과 확인하지 않은 사항

### 1.1 실제 확인

- Karpathy의 LLM Wiki 원안과 Microsoft의 구현 README, Quartz 공식 기능, MediaWiki의 변경 이력, Wikidata의 statement 구조, Stanford Encyclopedia of Philosophy의 편집 체계를 참고했다.[S01–S06]

- 기존 Windows 저장소를 읽기 전용으로 조사했다. 활성 통합 저장소는 `C:\Users\bongkunkim\code-chat`이며 `astrocode/`, `chat/`, `tour/`, `hidden/`이 있고 `techniques/`는 아직 없다.
- 현재 실제 Git 브랜치는 `desktop`이었다. 루트 AGENTS.md의 `main` 설명과 일치하지 않으므로 문서만 믿고 브랜치를 전환해서는 안 된다.
- 기존 변경은 `AGENTS.md`, `README.md`, `package.json`, `tour/public/licenses/third-party.txt`의 네 경로에서 확인됐다. 이 조사에서 수정하지 않았다.
- Library의 `CODEX_DATASET_GUIDE.md`를 읽었다. 가이드는 1,644건의 한국어 사례·이론과 288장 이미지를 설명한다. 압축 데이터 본문 전체나 이미지 전부를 이번에 검증한 것은 아니다.[S24]

### 1.2 아직 검증하지 않은 사항

세계의 모든 점성술 사이트를 수집하거나, 모든 고전의 판본을 대조하거나, Luna의 한국어·산스크리트어·고전한문 번역 품질을 실제 API로 평가하지 않았다. AstroWiki 일부 URL은 JavaScript 확인 화면으로 본문·라이선스 확인이 막혔다. Hellenistic Astrology 고전 목록의 직접 접속은 오류가 났고, Astro-Seek는 일부 검색 결과 수준의 확인에 머물렀다. 이런 자료는 “허가 완료·수집 완료”로 표시하지 않는다.[S18, S19, S23]

프로젝트 빌드·테스트·배포·Git 변경·유료 LLM 호출·대량 크롤링은 실행하지 않았다. 아래 수량·품질 수치는 모두 **계획상 목표**다.

LLM Wiki 원안과 Microsoft 구현은 개인 지식관리의 자동 정리를 강조한다. 본 서비스에서는 원문을 읽고 제안을 만드는 권한과 공개 문서를 승인하는 권한을 분리한다. Microsoft 구현의 VS Code 확장에는 Copilot 관련 전제도 있으므로, Camel을 그대로 꽂는 공개 백과 엔진이라고 가정하지 않는다.[S01, S02]

Quartz 자체를 그대로 쓰는 선택도 빠른 내부 출판에는 합리적이다. 다만 이번 목표는 학파별 조건, 구조화 규칙, Astrocode 예제와 편집 검토 화면이 핵심이므로, **공개 서비스는 Astro + React 일부 컴포넌트**, Quartz는 탐색 UX의 참고 모델로 권고한다. Astro와 Astrocode는 이름이 비슷하지만 다른 대상이다.[S03, S31]

## 3. 정보 구조: 단일 폴더 나무가 아니라 다중 분류

“전통 / 현대 / 예측 / 리로케이션”만으로 분류하면 같은 기법이 여러 폴더에 복제된다. 하나의 정식 문서 ID를 만들고 여러 진입 경로를 제공한다.

### 3.1 독립된 문서 종류

**기법 Technique**, **기법 변형 Variant**, **학파·전통 Tradition**, **개념 Concept**, **판단 규칙 Claim/Rule**, **계산 규약 Calculation Profile**, **저작 Work**, **판본·번역 Edition**, **저자·학자 Person**, **예제 Example**, **용어 Term**, **비교 문서 Comparison**를 구분한다.

저작과 판본은 특히 분리한다. 같은 고전의 원어 본문, 현대 영어 번역, 한국어 해설은 저작권과 문구, 페이지, 해석이 다를 수 있다. `work_id`만 연결하고 판본을 생략하면 검증할 수 없는 인용이 된다.

### 3.2 교차 필터

문서에는 전통·시대·언어·적용 분야·필요 자료·계산 방식·난이도·권리 상태·편집 검토 상태·계산 구현 상태를 붙인다. 예를 들어 “타지카 / 연간 예측 / 산스크리트 / 솔라 리턴 / 문헌 검토 완료 / 계산 미구현”이라는 조합을 검색할 수 있게 한다.

`part_of`, `prerequisite_for`, `variant_of`, `derived_from`, `analogous_to`, `contradicts_under_conditions`, `implemented_by`, `discussed_in`처럼 관계의 종류도 구분한다. `analogous_to`는 “동일한 기법”이나 “역사적으로 직접 전승됨”이라는 뜻으로 쓰지 않는다. 전승 관계는 별도 근거가 있어야 한다.

### 3.3 이견을 보존하는 원칙

리셉션, 공허한 달, 랏의 주야 반전, 다샤의 연간 길이, 하우스 경계, 프라이머리 디렉션의 키 등은 저자·학파별 규칙을 각각 저장한다. 모델이 충돌을 발견하면 삭제하거나 다수결로 결정하지 않고 비교 문서와 편집 쟁점으로 연결한다. 하나의 출처만 전하는 소수 학파는 그 사실을 밝히고 보존하되, 교차 검증된 보편 규칙처럼 표시하지 않는다.[S05]

역사적으로 논쟁적이거나 오늘날 권장하기 어려운 의료·수명·정치·금융 판단도 연구 대상으로 배제하지 않는다. 그러나 문헌 소개와 현대의 실제 의료·투자·안전 조언은 구분한다. 계산이 재현된다고 예측 효력이 검증됐다는 뜻은 아니다.

## 5. 자료원 전략과 수집의 우선순위

### 5.1 핵심 자료원

**Skyscript**는 서양 고전 문헌과 전문 해설의 입구로 사용한다. 문헌 목록을 따라 원저·판본을 찾되 현대 해설과 도판은 저작권 정책에 따라 허가를 받는다.[S07, S08]

**The Astrology Podcast**는 기법 설명과 실천가의 논점을 찾는 주요 1차 해설원으로 사용한다. 게시일·회차·발언자·원문 단락 또는 시각을 기록한다. 동영상에 접근할 수 있다는 이유만으로 전체 자막을 번역 재게시하지 않는다.[S09]

**Jagannatha Hora 및 계통별 교사 자료**는 인도 기법 명칭·적용 조건·계산 옵션을 발견하는 데 사용한다. Parashara와 Jaimini 등 계통 차이는 편집 과정에서 제거하지 않는다.[S10, S11]

**The Jewel of Annual Astrology**는 Sanskrit–English 비평판과 CC BY 4.0이 확인되는 유용한 우선 자료다. 타지카의 개념·규칙을 원문과 번역으로 대조하고, 공개 라이선스 조건을 충족하는 한국어 해설의 기반으로 삼는다. 이번 조사는 메타데이터·목차·라이선스 확인이며 책 전체의 내용 검증은 아니다.[S15, S35]

**Ptolemaeus Arabus et Latinus**는 아랍어·라틴어 전승과 판본·문헌 연결에 사용한다. **Rudhyar Archival Project**, **Centre for Psychological Astrology**, **Cosmic Patterns**는 현대 계열 저자·용어·도구를 탐색하는 각각의 출처다. 각 사이트의 자기평가나 홍보 문구를 백과의 사실판단으로 복사하지 않는다.[S13, S14, S16, S20]

**Men-Tsee-Khang**은 티베트 천문·점성 전통, **Wikisource의 고전 전사**는 동아시아 문헌 탐색의 출발점으로 삼는다. 전사본의 한자·기호 오류는 원본 이미지와 대조해야 하며, 한 판본만으로 전통 전체를 단정하지 않는다.[S12, S17]

**AstroWiki·Astro-Seek**는 특히 관련 용어와 계산 UX 탐색 후보이지만 이번의 접근·라이선스 미확정 상태를 그대로 기록한다. 우회 수집하지 않는다.[S18, S19]

### 5.2 대감님의 한국어 코퍼스

기존 가이드상 1,644건의 사례·이론과 288장 이미지는 한국어 용어·설명법·질문별 판단의 중요한 자산이다.[S24] 다만 다음 세 층으로 분리한다.

1. **한국어 편집 기준:** 용어, 문장, 판단 설명의 스타일을 참고한다. 다른 학파의 서로 다른 뜻까지 강제로 같은 용어로 통일하지 않는다.
2. **실전 사례:** 별도 사례 문서로 연결한다. 개인을 식별할 수 있는 출생·사건·관계 정보는 삭제·비식별화·허가 검토한다.
3. **추출된 규칙:** “이 사례에서 저자가 사용한 규칙”으로 귀속시킨다. 성공 사례에서 곧바로 모든 차트에 적용되는 보편 법칙을 생성하지 않는다.

가이드에는 JSONL 레코드 사이에 `---` 구분자가 있다고 명시되어 있다. 따라서 표준 JSONL 파서에 곧장 넣지 말고 원본 보존 후 구분자를 처리한 정규 JSONL을 생성해야 한다. 레코드 수·고유 ID·차트 좌표·시각·출처 URL은 실제 파일에서 다시 검증한다.[S24]

### 5.3 지속적 발견

초기 목록을 고정 상한으로 두지 않는다. 학파별 다국어 검색어 → 공개 문헌 목록 → 저자·저작 → 인용문헌 → 새로운 기법·이명 → 관련 문서의 순서로 확장한다. 검색 결과, 도서관·학술 서지, RSS·사이트맵, 공개 API를 각각 허용 범위에서 사용한다. Google/Bing 결과 페이지의 무단 대량 스크래핑을 전제로 하지 않는다.

영어만 중간 언어로 강제하지 않는다. 한문은 원문–한국어, 산스크리트는 원문–학술 번역–한국어, 아랍어·라틴어·독일어 등은 해당 언어 판본과 전문 번역을 함께 다룬다. 해당 언어를 검토할 사람이 없으면 “번역 검토 대기” 상태를 유지한다.

## 6. 수집·번역·공개 권한을 각각 확인한다

자료원마다 `fetch_automatically`, `store_full_text`, `send_to_external_llm`, `publish_translation`, `publish_images`를 **허용 / 불허 / 미확정**으로 따로 기록한다. 로그인 정보가 있다고 공개 재배포 권한이 생기는 것은 아니다.

|자료 상태|보존·처리 방침|공개 방식|
|---|---|---|
|공공영역이 확인된 원문|관할·판본·스캔 조건 확인 후 보존|출처·판본을 밝힌 해설·번역|
|CC BY 등 허용 라이선스|조건과 제3자 예외를 확인|표시·변경 고지·라이선스 조건 준수|
|CC BY-SA 등 동일조건 라이선스|라이선스의 연쇄 적용 범위 검토|문서/기여 단위로 구분, 전체를 독점 저작물로 표시하지 않음|
|현대 저작권 자료|허가 범위 내 보관 또는 서지·필요 최소 인용|독자적 종합 해설·정당한 인용·원문 링크; 전문 번역은 별도 허가|
|유료·회원 전용 자료|허용된 열람과 자동 처리 범위 확인|구독을 재배포 허가로 해석하지 않음|
|사용자 사례·타인 차트|권리·개인정보·외부 전송을 개별 검토|명시적으로 승인된 비식별 예제만 공개|
|미확정/접근 차단|메타데이터와 조사 상태만 기록|본문 자동 공개 금지|

Skyscript는 특히 현대 문장과 도판의 복제·번역 허가를 명시적으로 다룬다. 고전 원저의 저작권과 현대 번역자의 저작권도 별도다.[S08] CC BY 4.0은 출처 표시와 변경 고지 등 조건이 있으며, 플랫폼 전체가 아무 조건 없이 마음대로 이용할 수 있다는 의미가 아니다.[S35]

robots.txt는 준수하되 그것 자체를 법률상 접근권·저작권 허가로 간주하지 않는다.[S36] 권리 판단이 애매한 대량 재출판은 별도의 법률 검토 대상으로 둔다. 원문을 문장별로 바꿔 쓴 대체 번역본은 독자적 백과 해설로 포장하지 않는다.

## 7. 수집에서 공개까지의 파이프라인

```text
발견 후보 → 권리·접근·외부전송 확인 → 허용된 원문 확보
       → 원본 해시·판본·수집일 보존 → 문단/페이지/시각 분할
       → 개념·규칙·예외·출처 추출 → 한국어 용어와 번역 제안
       → 기호·수치·조건 검사 → 원문 대조·학파 검토
       → 편집 승인 → 링크·권리·수식·검색 검사
       → 고정 릴리스 → 배포 직전 산출물
```

### 7.1 수집 실행

HTTP 응답코드, 원 URL, canonical URL, 리다이렉트, 저자·날짜, 라이선스 근거, 수집일, 해시를 저장한다. 자동 접근은 도메인별 속도 제한과 조건부 요청을 사용한다. 같은 본문의 전재·복제 사이트는 하나의 출처 계보로 묶어 여러 독립 근거처럼 세지 않는다.

원문 HTML·PDF·자막은 허용된 경우에만 비공개 보관한다. 디지털 PDF는 텍스트 추출을 먼저 하고, 스캔 또는 수식·도표가 필요한 페이지만 이미지로 대조한다. OCR은 다른 방법이 없을 때 국소적으로 수행하고 결과를 원문처럼 신뢰하지 않는다. 페이지 좌표와 문단 경계가 유지돼야 인용을 검증할 수 있다.

### 7.2 추출 단위

한 덩어리 요약만 저장하지 않는다. 규칙의 전제·행동·예외·사용 학파·판본·문단을 연결한다. 추출 모델이 모르는 인용문헌을 새로 만들지 못하게 실제 source ID 목록만 허용한다. 모델이 언급한 출처는 원문에서 실제로 확인됐을 때만 유효하다.

### 7.3 변경과 삭제

새 원문 해시가 발견되면 영향을 받는 주장·번역·예제만 갱신 후보로 만든다. 사람의 기존 편집은 자동 덮어쓰지 않는다. 수정 제안은 기반 버전과 함께 저장해 충돌을 검출한다.

원문 링크가 끊겼다고 기존 백과 문서를 통째로 자동 삭제하지 않는다. 접근 불가와 권리 철회는 구분한다. 법적 삭제나 개인정보 삭제가 필요하면 원문·캐시·검색·요약·임베딩·예제의 파생 관계를 따라 삭제 또는 비공개 처리하며, 불필요한 민감정보를 감사 로그에 남기지 않는다.

### 7.4 보안

수집 문서는 자료이지 명령이 아니다. “비밀키를 보내라” 같은 원문 내 텍스트를 실행하지 않는다. 크롤러에는 내부 IP·localhost·메타데이터 주소·악성 리다이렉트 접근 차단, 파일 크기 제한, 압축 폭탄 방지, MIME 검사 등을 둔다.

스크래핑한 Markdown을 임의 MDX 코드로 실행하지 않는다. HTML·SVG·URL을 정제하고, 다운로드 파일 이름과 경로를 검증한다. 외부 문서를 읽는 프로세스에는 Git push·배포·비밀키 조회 권한을 주지 않는다.

## 8. 한국어 번역과 AI 모델 운영

### 8.1 권고하는 역할 분담

**Camel 계열 모델:** 외부 전송 권한이 확인된 자료의 분할 번역·용어 후보·초안 작성.  
**공식 OAuth 로그인 편집 도구/현재의 AI 협업:** 대표 문서·용어집·어려운 대조·수정 제안.  
**승인된 로컬 모델:** 외부 전송이 부적절한 자료의 비공개 처리 후보.  
**사람 편집자:** 전문 용어·학파 조건·원문 근거·공개 승인.

특정 모델이 고전어와 점성술을 정확히 번역한다고 미리 확정하지 않는다. 최초 100개 시험 구간을 실제 자료에서 선정하고, 산문·규칙·부정문·숫자·수식·고전어·중역 위험을 나누어 평가한다. 동일 모델의 자기 검토만으로 승인하지 않는다.

### 8.2 Camel의 중요한 제약

Camel Stream 공식 문서는 모델을 가변적으로 선택하며 특정 모델·버전을 보장하지 않는다고 설명한다. 따라서 “Luna 고정”을 코드와 서비스 약속으로 박아두지 않는다. 제공된 계정에서 실제 허용 모델 ID와 반환 메타데이터를 확인하고, `provider`, `requested_model`, `reported_model`, `prompt_version`, `glossary_version`, `source_hash`를 기록한다. 반환된 모델 이름도 공급자 보고 값이지 독립 검증된 실체라는 뜻은 아니다.[S25, S30]

더 중요한 것은 표준 플랜에서 API 콘텐츠가 보관·학습·광고 등에 사용될 수 있으며 기본 opt-out이 없다는 약관이다. 모든 인터넷 자료와 사용자 코퍼스를 그대로 보내는 구조는 권고하지 않는다. **웹 공개 권한과 AI 사업자에게 해당 조건으로 전송할 권한은 별개**다. 대감님 소유 자료라도 개인정보·타인 자료·향후 비공개 운영 의도가 있으면 추가 검토해야 한다. 필요한 경우 별도 무학습·무보관 계약 또는 승인된 로컬 처리 경로를 쓴다.[S26, S27]

### 8.3 기존 서비스와 동시성

무제한 토큰은 무제한 병렬 요청이 아니다. Camel의 제한은 같은 계정의 여러 API 키에 걸쳐 적용된다.[S26, S29]

공통 작업 조정기를 두고 대화형 호라리 요청을 백과 번역보다 우선한다. 다만 이미 시작한 장기 생성은 즉시 선점하지 못할 수 있으므로 짧은 구간, 제한된 작업 길이, 큐 시작 전 유휴 확인이 필요하다. 모든 프로젝트가 같은 조정기를 사용하지 않으면 전역 우선순위는 보장할 수 없다. 별도 스트림 증설은 필요와 예산을 확인한 뒤 결정한다.

열린 스트리밍 연결이 대기 중이면 중복 요청을 만들지 않는다. 429는 Retry-After, 503은 지수 지연·지터·횟수 상한을 적용한다. 401/402 등은 무한 재시도하지 않고 중단·알림한다. 원문 해시와 작업 버전 기반으로 중복을 막고, 중단된 작업은 체크포인트부터 재개한다.[S29]

### 8.4 OAuth와 직접 번역의 위치

공식 로그인으로 허용되는 Codex·편집 도구를 사용해 문서 파일을 번역·수정하는 경로는 고려할 수 있다. 하지만 개인 구독의 OAuth 토큰을 추출해서 공개 웹서비스의 무제한 백엔드 API로 취급하지 않는다. 공식 문서가 지원하는 자동화·인증 방식과 실제 계정의 한도를 확인해야 한다.[S34]

현재의 AI 협업으로 초기 용어집·대표 문서·비교 문서·검수 기준을 작성하는 것은 유용하다. 그것을 대량 자료의 계속 돌아가는 운영 번역 서버로 설계하지는 않는다.

### 8.5 번역 검수 규칙

용어집은 한국어 권장어, 영어·원어, 이명, 학파별 의미, 사용 금지 혼동, 출처, 승인자를 가진다. 예를 들어 progression / profection / direction은 구분하며, 같은 `reception`이라도 학파별 조건을 보존한다. 도수·분·초·주야·순역·행성 기호·부정문·예외 조항은 별도 검증한다.

번역 메모리는 `원문해시 + 분할규약 + 용어집버전 + 번역정책버전`에 묶는다. 최종 승인 번역과 모델 초안은 별도 보관한다. 자동 검수는 원문 구간에 대한 근거를 제시해야 하며, 이해가 안 되는 곳을 자연스러운 한국어로 메우지 말고 의문 지점으로 남긴다.

```text
어떤 조건에서 적용하는가
단계별 절차와 예외
계산식 또는 판단 규칙
학파·저자별 변형과 차이
합성/동의된 사례와 결과 재현
흔한 혼동과 한계
관련 기법 · 선행/후속 학습
출처 · 판본 · 단락/쪽/시각 · 문서 버전 · 편집 이력
```

예를 들어 “빛의 전달”은 서술 한 문장으로 끝내지 않고, 선택한 판본에서 요구하는 행성·분리·접근·수용 조건을 해당 출처와 연결한다. 서로 다른 저자의 조건은 표의 다른 행이 된다. **여기서는 그 조건을 임의로 확정하지 않으며, 실제 집필 시 판본 단위 검증으로 채운다.**

공개 배지는 최소 네 축으로 나눈다. **원문 대조 여부 / 전문 편집 여부 / 계산 구현 여부 / 경험적 검증 상태**다. 하나의 초록색 “검증 완료”로 모두를 대신하지 않는다.

## 10. 화면과 탐색 경험

첫 화면은 거대한 AI 채팅창이나 별자리 배경이 아니라 검색과 지식 탐색을 중심에 둔다. 로고, 짧은 설명, 한국어·영어·원어 검색창, 학파/목적/기법별 탐색, 편집 완료 추천 문서, 최근 개정, 수집 공백을 배치한다. 문서 수는 승인 문서와 후보를 분리해 표시한다.

데스크톱 문서는 왼쪽에 탐색, 가운데 본문, 오른쪽에 목차·관련 문서를 둔다. 모바일에서는 본문을 먼저 보여주고 목차·필터는 접어 둔다. 기본 디자인은 밝은 종이색 또는 차분한 중성 배경, 짙은 본문, 제한된 강조색, 충분한 줄간격, 긴 글에 적합한 폭이다. 네온·글래스모피즘·우주 배경·의미 없는 AI 장식 이미지는 피한다.

용어에 마우스를 올리거나 모바일에서 누르면 짧은 정의와 링크를 보여준다. 그래프는 현재 문서 주변의 제한된 노드만 표시하고, 관계 종류별로 필터한다. 학파 비교 화면은 용어·전제·규칙·공식·예외·출처를 같은 행에서 비교한다.

“읽기 / 출처 / 비교 / 토론 / 역사 / 수정 제안”을 제공한다. 초기에는 공개 읽기와 수정 제안을 열고, 즉시 익명 본문 편집은 열지 않는다. 동의 없는 사례·연락처·차트 자료가 토론을 통해 공개되지 않도록 검토한다.

D1·R2는 필요가 확인됐을 때 생성한다. 출시 준비 단계의 로컬 샘플 때문에 운영 데이터베이스를 미리 만들지 않는다. 다중 편집 요구가 아직 없으면 Git 기반 편집 제안만으로 시작해도 된다.

### 11.3 Canonical source of truth

승인된 원고·구조화 규칙·릴리스 manifest의 권위는 버전 저장소에 둔다. 편집 DB는 작업 상태·수정 제안·읽기용 파생 인덱스를 보관한다. 동일 본문을 Git와 DB에서 각자 수정하는 설계는 금지한다. `base_revision`을 비교해 동시 편집 충돌을 탐지한다.

원문 저장소는 Git·공개 dist·공개 R2에 들어가지 않는다. 공개 웹 빌드는 승인 콘텐츠만 허용하는 allowlist 입력으로 실행한다. 주석·원본 source map·검색 인덱스·다운로드 파일에도 원문 또는 비밀정보가 새지 않도록 검사한다.

### 11.4 실제 재사용할 부분과 새로 필요한 부분

`astrocode/app/lib/ask-ai-horary-types.ts` 4–13행의 요청은 `question`과 `reports.koreanHorary/aiEvidence`를 받는 **호라리 전용 계약**이다. 이것을 일반 번역 API로 오용하지 않는다. 대신 input hash, `requestedModel/reportedModel`, 상태 전이와 전송 패턴을 참고해 별도 번역 작업 계약을 만든다.

`astrocode/app/lib/chart-provenance.ts`는 source/derived 차트의 계보를 다룬다. 이는 예제의 출처 연결에 참고할 수 있으나, 모든 계산 설정을 재현하는 완성된 manifest가 이미 있다는 뜻은 아니다. 위키 예제에는 별도의 계산 규약과 입력·출력 검증이 필요하다.

`chat/wrangler.jsonc`의 Astrocode 인증 서비스 연결과 `hidden/wrangler.jsonc`의 Astrocode service binding은 통합 방향을 보여준다. 그러나 기존 ChatHub에 위키 원고와 대량 수집 큐를 얹지 않는다. 토론은 필요한 경우 Chat의 해당 문맥으로 이동시키고, SSO·링크 계약은 실제 통합 때 다시 검증한다. 공개 문서를 읽는 데 로그인은 요구하지 않는다.

## 12. 한국어 검색

Pagefind 공식 지원표에는 한국어 UI는 있으나 한국어 word stemming은 지원하지 않는 것으로 표시되어 있다.[S32] 따라서 “한국어 지원”을 그대로 검색 품질 보장으로 해석하지 않는다.

초기에는 제목·권장어·영어·원어·동의어·오타·붙여쓰기/띄어쓰기 변형의 전용 용어 인덱스를 만들고 본문 검색과 결합한다. Unicode 정규화는 원문 표기를 덮어쓰지 않고 검색용 필드에만 적용한다. 한국어 2/3글자 n-gram 같은 추가 방식은 자료 크기·재현율·오탐을 실제로 평가해 선택한다.

최소 100개의 한국어·영어·한자·혼동어 질의에 정답 문서를 지정한다. “빛의 전달 / translation of light”, “프로펙션 / 프로그레션”, “리셉션 / 수용”, “칠정사여 / 七政四餘” 같은 예를 포함한다. 정답이 없는 검색도 숨기지 말고 “찾지 못함·제보” 경로를 제공한다.

벡터 검색은 초기 필수 조건이 아니다. 도입하더라도 승인 문서만 대상으로 하며, 원문 권리와 외부 임베딩 전송권을 별도로 확인한다. 검색 순위는 모델의 자신감보다 제목·용어 일치·학파 조건·출처·검토 상태를 우선한다.

## 13. Astrocode 예제와 계산 검증

문서화와 계산 구현을 분리한다. 어떤 기법을 백과에 수록했다는 이유로 Astrocode에서 실행할 수 있다고 표시하지 않는다. `documented / implemented / fixture-tested`를 별도로 관리한다.

예제는 합성 차트 또는 공개에 동의한 사례를 기본으로 하고, 날짜·시간대·달력·위경도·황도·아야남샤·하우스·노드·좌표계·주야 판정·세차·방향/키·기간 길이·계산엔진 버전을 보존한다. 입력 해시, 코드 버전, 기대 출력과 허용 오차도 묶는다. 본문 설명과 계산 결과가 서로 다른 규약을 쓰면 빌드를 막는다.

각 학파의 문헌 규칙을 구현한 순수 계산 함수와 테스트를 만들고, 실제 차트로 열기 기능은 기존 Astrocode의 검증된 입력 계약을 사용한다. 지원하지 않는 조합은 명시적으로 오류 또는 미지원으로 표시한다. 지도·차트 이미지는 의미가 있는 자체 렌더링을 우선하며, 상용 프로그램의 도판을 복사하지 않는다.

Swiss Ephemeris 사용은 AGPL 또는 Professional 라이선스 선택과 의무를 실제 프로젝트 조건에서 확인해야 한다. 공식 안내는 공개 서비스 활성화 전에 선택하라고 명시한다. 단순히 기존 코드에 들어 있다는 이유로 신규 서비스의 의무가 자동 해결됐다고 가정하지 않는다.[S21]

## 14. 실행 순서와 단계별 통과 조건

기간을 임의로 약속하기보다 산출물과 통과 조건으로 관리한다.

|단계|실제 할 일|통과 조건|
|---|---|---|
|A. 규약 확정|저장소 상태 재확인, 분류·ID·권리표·편집정책·번역 규약|모든 필드와 책임자, 공개 금지 조건 합의|

|C. 번역·검색 평가|100개 번역 구간과 100개 검색 질의, Camel 계정/모델 실측|중대 오류 통과 기준 충족, 비용·대기 병목 계측|
|D. 폭넓은 수집|455개 후보의 이명 정리·문헌 연결, 인용·다국어 탐색으로 확대|후보·근거 확인·번역·심사·권리 상태 분리|
|E. 출시 후보 편집|완성 문서 150개를 목표로 검토, 동시 진행 중인 문서는 비공개|핵심 주장 인용과 권리·역사·변형 표시 충족|
|F. 통합 검증|Astrocode 예제, 공개/관리 권한, UI·모바일·검색·보안·링크·성능|미지원 기능을 성공으로 보이지 않고 승인 콘텐츠만 노출|
|G. 배포 직전 동결|고정 빌드·manifest·백업·롤백·배포 절차·미해결 목록|운영 변경 없이 release-candidate 묶음 완성|

150개는 출시 후보에 대한 **편집 목표**이지 전체 기법의 상한이 아니다. 각 학파는 원칙적으로 수집 범위에 남아 있으며, 우선 30개 문서는 서양 전통만으로 채우지 않는다. 30개 대표 문서의 권고 배분은 서양 전통 7, 현대·관계 4, 인도 7, 동아시아 3, 티베트 2, 공간·문데인 3, 공통 계산·문헌 4다. 난도에 따라 조정하되 소수 전통이 영구적으로 밀리지 않도록 한다.

빈 문서를 대량 공개해 수량을 늘리지 않는다. 제목만 있는 후보는 내부 목록으로 유지하고, 공개 수집 현황에는 숫자·공백 상태만 보여줄 수 있다.

## 16. 비용·처리량·유지보수

첫 번째 원칙은 **방문자가 문서를 읽을 때 AI 비용이 발생하지 않도록 하는 것**이다. 두 번째는 **수집·번역·검수를 캐시하고 변경분만 다시 처리하는 것**이다.

비용은 모델 구독/스트림, 허용 원문 저장, 처리용 컴퓨터, 전용 API 호출, CI 빌드, 검색 인덱스, 라이선스/허가, 편집·언어 검토로 나눈다. 특히 사람의 전문 검토가 병목이므로 토큰 단가만으로 전체 사업 비용을 계산하지 않는다.

Camel은 공식 약관상 토큰당 과금이 아닌 스트림 단위이고 동시성이 계정 전체에 적용된다.[S26] 실제 계약·추가 스트림 필요 여부·가격은 API 제공 시 재확인한다. Cloudflare의 정적 자산 제공은 별도 Worker 실행과 과금 구조가 다르다.[S33] 이 사실만으로 전체 운영비가 0원이라고 결론 내리지 않는다.

파일럿에서 다음 값을 측정한다: 원문 1만 자당 추출 오류, 한 구간의 평균 대기·생성 시간, 재시도율, 번역 후 사람 수정량, 문서당 검토 부담, 이미지/원문 저장량, 빌드 시간, 검색 인덱스 크기. 전체 규모 산정은 이 실측값으로 한다.

배포 후 운영 계획에는 변경 원문 감지, 링크 확인, 모델·약관 변경 확인, 용어집 버전 업데이트, 보안 업데이트, 제보·삭제 요청, 학파별 공백 관리가 포함된다. 이번 요청에서는 그러한 자동 작업을 실제로 예약하거나 실행하지 않았다.

## 17. 편집 권한과 지식의 신뢰성

대감님은 총괄 편집과 한국어 용어 기준을 담당하는 구조가 적합하다. 다만 모든 언어·학파를 한 사람이 이미 검증할 수 있다고 가정하지 않는다. 분야·언어 검토가 필요한 문서는 담당 검토자 미확보를 명시한다.

역할은 수집자, 번역 초안 작성자, 원문 대조 검토자, 분야 편집자, 발행 승인자로 구분한다. 초기 운영에서 한 사람이 여러 역할을 맡더라도 기록은 구분한다. 모델 이름을 사람 검토자 자리에 넣거나 자동검수 통과를 전문가 승인으로 표시하지 않는다.

문서는 “해당 전통은 이렇게 주장한다”, “그 역사적 저작에서 확인된다”, “이 공식으로 계산된다”, “경험적 연구에서는 이 결과가 보고됐다”를 구분한다. 반복 인용과 증언을 독립적인 효과 입증으로 계산하지 않는다. 반대 결과와 미확인 결과도 자료가 있으면 같은 기준으로 다룬다.

## 18. 배포 직전 반드시 남겨야 할 산출물

- 승인된 원고·용어·학파·주장·판본·예제의 버전 고정 목록.
- 해당 원고만 포함하는 정적 HTML·검색 인덱스·공개 자산.
- 각 산출물의 해시, 코드 커밋, 빌드 도구 버전, 라이선스 목록이 들어 있는 release manifest.
- 단위·계산·검색·문서·보안·UI 테스트의 실제 실행 결과와 실행 환경.
- 운영 비밀키 이름 목록과 저장 위치 정책. **비밀키 값은 포함하지 않는다.**
- 새 위키에만 적용되는 배포 절차, DNS 연결 절차, 롤백·삭제·백업 절차.
- 미해결 사항, 원문 접근 실패, 미확정 라이선스, 미구현 계산 기능, 공개 제외 문서 목록.

배포 직전 완료 기준은 “이제 공개 명령만 실행하면 되는 검증된 산출물이 있다”는 것이다. 지금 제공하는 것은 그 상태를 만들기 위한 설계·조사 패키지이지 그 산출물 자체가 아니다.
