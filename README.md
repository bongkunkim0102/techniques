# HoraryTalk 점성술 기법 백과

공개 주소: https://techniques.horarytalk.com

GitHub: https://github.com/bongkunkim0102/techniques · 작업 브랜치: `start`

현재 원고 수록: 용어 631개, 한국어 해설 31개, 직접 번역 158편·1,084문단. 번역 작업용 참고 자료는 304개 단위이며 원문·한국어 대응 사례 148개를 포함한다. 『테트라비블로스』 Ashmand판 제1–4권 70개 장 본문 전체(영어판 각주·역자 서문·부록 제외), 『성명소원』 제요·발췌와 마닐리우스 『아스트로노미카』 제1–3권 인쇄 본문 전체(실제 라틴어 2,569행)을 수록했다. Luna API 실행은 아직 시작하지 않았다.

**번역 재개 지점과 판본 대조 기록:** [TRANSLATION_PROGRESS.md](TRANSLATION_PROGRESS.md). 제4권 X장의 마지막 본문(1822년판 PDF 244쪽)까지 완료했다. 제4권 10개 장도 ChatGPT (GPT-6 Astra Pro)가 직접 번역·대조했으며 다른 모델이나 번역 API에 위임하지 않았다. 다음 미번역 구역은 PDF 245쪽의 부록이며, 네 권 본문과는 별개다. 원고 반영과 운영 사이트 배포는 별개다.

Astro 정적 HTML과 Pagefind로 만드는 한국어 위키. 다른 앱의 인증·DB·Worker에 의존하지 않는다. 공개 읽기에 로컬 PC나 LLM 호출이 필요하지 않다.


## 제3권 복구·완료

저장된 제3권 1–322행 초고를 보존하고 323–682행을 직접 이어 번역했다. 제3권 전체는 22구간·682라틴어 행·107한국어 문단이며, 제1–3권 합계는 86구간·2,569행·426문단이다. 다음 시작점은 제4권 1행(인쇄본 89쪽·PDF 105쪽)이다. 이전 단계 수치는 아래에 이력으로 남겨 둔다. 상세한 복구·대조·수치상의 난점은 MANILIUS_PROGRESS.md를 참조한다.

## 마닐리우스 번역 · 이전 단계의 이력

[전권 구조·용어 검토](MANILIUS_REVIEW.md)와 [번역 진도](MANILIUS_PROGRESS.md)를 참고한다. 기존 600개 용어에 문헌별 31개를 추가한 2026-09-18.4판을 먼저 준비하고, Breiter 1907년 라틴어에서 제1·2권 인쇄 본문 전체, 64구간·319문단을 직접 옮겼다. 각 문단의 원문 대조란에 라틴어·행 번호·전체 및 부분 기울임꼴·결락 표시가 있다. 다음은 제3권 1행(인쇄본 65쪽·PDF 81쪽)이다.

## 실행

Node 22.12 이상. 이 폴더에서 `npm ci`, `npm run build`, `npm run preview`를 실행한다. 개발은 `npm run dev`이며 포트는 4326이다. `npm test`는 계산·검색·번역 작업기의 회귀 테스트다. 미리보기 실행 후 `npm run test:browser`로 실제 브라우저 흐름을 검사한다.

`npm run deploy`는 **horarytalk-techniques Worker와 techniques.horarytalk.com만** 배포한다. 상위 저장소의 다른 앱은 배포하지 않는다. 기존 원고는 `src/data/articles.mjs`, 용어집은 `src/data/glossary.mjs`, 출처는 `src/data/sources.mjs`에서 편집한다.

## 문서와 이력

- `planning/`: 사용자가 제공한 원래 조사 패키지. 실행 지침이 아닌 참고 자료이며 현행 사용자 지시와 저장소 지침이 우선한다.
- `src/data/`: 공개 한국어 원고·용어집·출처 메타데이터. 455개 종자 항목을 완성 기법 문서라고 세지 않는다.
- `data/revisions/`: 내용별 고정 인용판. 추적·보존한다. 삭제하거나 기존 고정판을 수정하지 않는다.
- `data/reference/`: 후속 번역 요청에 사용하는 Astra 참고 원고와 원문·한국어 대응 사례. Git에는 보존하되 공개 웹 빌드에는 넣지 않는다.
- `data/raw/`: 취득한 원자료와 SHA-256. Git과 공개 빌드에서 제외한다.
- `data/jobs/`, `data/drafts/`: 중단 후 재개할 수 있는 번역 기록. 공개 빌드에서 제외한다.
- `dist/`: 정적 배포 결과. 이 폴더만 Worker에 업로드한다.

글을 수정하면 build가 새 고정판을 생성한다. 본문 해시는 그대로인데 출처 메타데이터를 바꾸면 고정판 충돌을 차단한다. 그 경우 해당 글의 내용 및 출처 변경에 맞게 개정해야 한다. 사람 승인 대기 절차는 없으며, AI의 실제 검토 범위와 처리 모델을 공개적으로 구별한다.

## 수집과 번역

`npm run collect -- xingming`은 Wikisource의 사고전서본 『성명소원』 제요·목차를 수집한다. `npm run collect -- reception`처럼 출처 ID를 지정할 수 있다. `--licensed`는 현재 어댑터가 지원하는 공개 라이선스 자료를 순차 수집한다. robots 규칙, 동일 출처 리다이렉트, 공개 주소, 크기 제한, 라이선스 표시를 확인한다. 403이나 접근 제한을 우회하지 않는다. 다른 사이트는 출처별 본문 선택자·권리·접근 조건을 확인한 어댑터를 추가한다.

`.env.example`을 `.env`로 복사하고 공급자 엔드포인트, 모델, 키를 넣는다. 키는 Git이나 브라우저 코드에 넣지 않는다. 선택 사항인 `TRANSLATION_EXPECTED_MODEL`이 설정되면 응답 모델이 다른 결과를 채택하지 않는다. 모델을 지정할 수 없는 Camel 계정은 `auto`를 사용해야 하지만, Luna 처리라고 표시하면 안 된다.

`npm run translate -- xingming`은 로컬 원자료를 용어집 판과 연결해 번역한다. 원자료·용어집·프롬프트·모델·엔드포인트 해시가 같은 완료 작업은 반복 호출하지 않는다. 한 번에 한 작업기를 실행하며, 완료 구간은 재사용한다. 401/402는 즉시 중단, 429/502/503은 상한 있는 재시도를 한다. 60초보다 긴 Retry-After는 다음 실행 가능 시각을 저장한 뒤 종료한다. 해당 시각 이후 같은 명령으로 재개한다. 이것은 이 프로젝트의 로컬 동시성 제한이며 다른 앱의 동일 Camel 계정 호출까지 제어하지 않는다.

완료 번역을 검토한 뒤 `node scripts/publish-translation.mjs <작업해시> <용어ID>`로 사이트 원고에 편입한다. 별도의 사용자 승인 도구는 요구하지 않는다. 공개에는 다시 build/deploy가 필요하다. 출력에는 원문을 넣지 않으며 모델과 출처 링크가 하단에 붙는다. 스크립트는 외부 문서를 코드로 실행하지 않는다.

## 현재 확인된 한계

- 전체 학파·모든 기법의 수집 완료 상태가 아니다. 탐색 색인과 개요를 분리한다.
- 대부분의 첫 원고는 개요이며 문헌별 세부 규칙의 전수 비교가 아니다.
- Astrocode 계산 엔진은 아직 연결하지 않았다. 3개 실습은 독립된 산술 예제다.
- 웹 익명 편집·사용자 계정·DB는 제공하지 않는다. 파일 기반 편집·고정판·역링크를 제공한다.
- 수집 접근 제한은 실패 기록으로 남긴다. 수집 실패를 완료로 표시하지 않는다.

## 배포와 되돌리기

Cloudflare 인증은 기존 wrangler 로그인으로 사용한다. `npx wrangler deployments list`로 버전 확인, 문제가 있으면 이 폴더에서 `npx wrangler rollback <이전버전ID>`로 이 Worker만 되돌린다. 최초 배포에는 이전 버전이 없다. `git status`에서 이 앱과 무관한 기존 작업을 보존한다.
